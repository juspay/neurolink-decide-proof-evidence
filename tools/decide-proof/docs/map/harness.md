# harness

## summary
ScaleDown (15 Oct) and SubQ Snap (13 Oct) share one chain: Decision Index kit (python http engine) -> observer_clef.mjs :18992 -> shim :18991 (byte-identical shim-luna.mjs, SHIM_PROVIDER=typesafe) -> NeuroLink 12.47.0 decide() typesafe provider -> guard (NODE_OPTIONS --import, replaces fetch, same node process as the shim) -> [ScaleDown only: rewrite_scaledown.mjs path /v1/systemone->/v1/scaledown, Bearer->x-api-key, state move] -> provider. The real key (SCALEDOWN_API_KEY, read by name from marketing/.env) reaches only the shim, as TYPESAFE_API_KEY, via exec_clean. No boundary records full request bodies: observer and guard log hashes, sizes, status, usage and timing; only the kit's results.jsonl keeps response bodies (no request). Join key: ledger n == moves seq (verified on 3 runs). Provider specifics are hardcoded constants in renamed script copies; there is no config file and the runner accepts only banking77|clinc. Pins (kit 87d4650b, runner f4c9f36c, shim ff25d948, observer 728e84ba, rows 1629c6fb/a0fbb6a5, NeuroLink 12.47.0) and the 18-file freeze were re-verified on disk today. The safety gates (confirm vars, caps, ceiling file, STOP files, proxy refusal exit 14, freeze exit 15, host allowlist, one in flight) are all worth keeping. Sections below give files, exact field names, examples and line cites.

## 4 Where requests and responses are logged
Short answer: no boundary keeps full request bodies, and only the kit's own results file keeps response bodies.
- kit->shim (observer, OBS=~/Developer/temp/neurolink-fork/marketing/data/social/decision-index-clinc150-2026-10-06/clef/observer_clef.mjs): holds the whole request Buffer (:76) and response Buffer (:85) in memory, forwards byte for byte, writes one line (:89) with sizes, response sha256, per-question instructions sha256, option count, probability sums, usage. No text, no headers; error text first 300 chars. It sees the SHIM's answers (wire shape {model,answers,usage:{input_tokens,output_tokens}}), not ScaleDown's raw reply; the shim drops usage.cost.
- shim->provider wire (guard fetch wrapper, SD/guard_scaledown.mjs): the final outgoing body is prepared.init.body, handed to realFetch at :281; only its length is used (bodyCharsOf :208). The response is cloned (:293) and read as text (:346; error text :350), parsed only for usage.input_tokens, usage.output_tokens, usage.cost, model; the ledger line (:329) stores those numbers. Non-2xx bodies go scrubbed to errors/errors-<id>.jsonl (<=2000 chars, :361,:371). Headers: only rate-limit header values and other header NAMES.
- rewrite moves log: hashes and lengths of the moved utterance, never text.
- kit results.jsonl (DI/runs-scaledown/<id>/results.jsonl): full parsed response per row (all probabilities, usage) but no request; payload_sha256 ties it to the row. Probe/pilot copies are committed in SD/kit-run-files/; full-run ones are not (only sha256).
- Request bodies are reproducible, not recorded: rows file (state {}, q1.instructions "<frame>\n<utterance>", criteria option_N -> label) plus the deterministic rewrite; the lead re-derived all 8,580 outgoing bodies independently with 0 mismatches (PROTOCOL.md Addendum 2 item 6).
- Only full request/response pairs on disk: the 8 hand probes SD/probes/*.json (probe.py; request without credential + response) and the fake's FAKE_CAPTURE_BODIES (test only).
- Secret-bearing spots: shim->provider request headers (Authorization Bearer before the rewrite, x-api-key after). Bodies hold public dataset text, criteria, model id. Existing masking code: shim collectSecrets/makeScrub (shim:20-26: env values >=8 chars whose name ends KEY|TOKEN|BASE_URL|ACCOUNT_ID|MODEL, plus \S{0,8}***\S{0,8}) and guard scrub (:98-102: GUARD_KEY_VARS values, Bearer tokens, sk-... tokens, ***). scan_scaledown.py re-checks the folder by value, prefix/suffix and token hash.
- Join keys: ledger n == moves seq (checked: banking77-full 3086/3086, clinc-full 5508/5508, banking77-pilot 54/54). Observer seq is a separate kit-side counter (banking77-full: 3084 observer calls vs 3086 ledger attempts, consistent with NeuroLink's one retry after a 504 and a network error); observer and ledger are joined by time span or instruction hash in the recount and summary.

## 6 Safety gates worth keeping

- Freeze check exit 15; pin checks exit 10/11/12; port in use exit 5 (18991, 18992 via lsof, :167); observer/shim did not start 8/13.
- STOP files: a run refuses to start if any STOP-*.json exists in the folder (exit 4, :164-165); the guard writes STOP-<id>.json and a watcher kills the kit within ~0.4 s (:212); no resume-after-STOP; refuses to reuse an existing ledger/observer/out path (:166; use SD_RUN_SUFFIX).

- Rewrite fail-closed list (rewrite_scaledown.mjs:104-163): host, scheme, port, path, method, Request object, headers, single Authorization Bearer equal to the process key, no pre-existing x-api-key, body string with model == expected, state/question shape, frame, empty utterance, body round-trip, concurrency; exit 22.

- Secrets: key only in the shim env via exec_clean; observer and kit never see it; scan_scaledown.py exits 2 unless SCALEDOWN_API_KEY is in its scan set; preflight prints a count, not a value.
